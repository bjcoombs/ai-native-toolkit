- issue #1180, three GitLab and Python lint readings. A lone `- mypy` (any lone linter) under a
  GitLab `script:` key now counts in `test_or_lint_configured` and `enforced_check_runs` as it
  already did in `lint_runs`. `tox -e <env>` and `nox -s <session>` read through to the commands
  the root `tox.ini`, `tox.toml` or `noxfile.py` gives that environment, so one that runs a
  linter reads `lint_runs` true; one not read whole stays null (`check_target`). GitLab jobs
  are read as GitLab merges them: a job defined in the root file and an include, a job using
  `extends:`, and a `before_script:` taken from `default:` are read once with their effective
  keys, so a root `when: manual`, `allow_failure: true` or replacement `script:` over an
  included lint job, or a template's `allow_failure: true`, no longer reads as an enforced
  check. A merge that cannot be settled (an include under `rules:`, an anchor merge, an
  `extends:` parent not read) reads not measured (`unknown_trigger`). `ci_checks` revision 7.
