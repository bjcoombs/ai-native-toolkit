- issue #822, doc staleness: a nearest-ancestor base doc is measured against the code files
  directly in its own directory, not its whole subtree, so commits deep in a large tree no
  longer make a root doc stale. A rename after the doc's last change of a direct child the doc
  still names makes it stale; a deeper rename does not. A base doc with no code beside it
  leaves `measured_docs`. Below 20 measured docs `stale_pct` is null with
  `stale_pct_reason` `too_few_measured_docs`, so doc freshness reads not measured.
