- issue #1507, pointer chains and the `./` sibling link. A bare-pointer root `AGENTS.md` is
  followed through further bare pointers to the file with content: with `AGENTS.md` = `See
  CLAUDE.md.` and `CLAUDE.md` = `See GEMINI.md.`, `GEMINI.md` is canonical in
  `agent_consistency` and both pointers link as `pointer`, where before `CLAUDE.md` was
  canonical holding only a pointer and `GEMINI.md` read `independent`. A chain that reaches
  one of its files again, imports one back or is a symlink back is no delegation, and
  `AGENTS.md` stays canonical. A pointer may also link the sibling as `[CLAUDE.md](./CLAUDE.md)`;
  every other form stays as #1505 fixed it. On a repository with that layout, `unlinked` can fall
  and the `agent-consistency` row can rise.
