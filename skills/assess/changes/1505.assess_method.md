- issue #1505, a bare pointer file is delegation. A root instruction file is a bare pointer
  when, after an optional H1 and blank lines, its one line fully matches one of a fixed set of
  forms (`See X.`, `Read X.`, `Follow X.`, `The instructions for this repository live in X.`,
  `Instructions live in X.`, `Follow the project instructions in X.`), where X is the sibling
  file's name or `[name](name)`, optionally backticked, case-insensitive. A root `AGENTS.md`
  that is a bare pointer makes the file it names canonical in `agent_consistency` and links
  as `pointer`, and a third tool's symlink, import or pointer to that `AGENTS.md` still links
  (`GEMINI.md` = `@AGENTS.md` reads `import`); a bare-pointer `CLAUDE.md` naming `AGENTS.md` links as `pointer` for Claude
  Code too. `claude_shadows_agents` is not raised for the pointer file itself; any other
  `CLAUDE.md` in the directory (`.claude/CLAUDE.md`) is still compared. Two files that point
  at each other, or a pointer whose target imports it back, are no delegation. Any other
  wording, a second line, an HTML comment, a negation or a path such as `docs/CLAUDE.md` stays
  a separate file, as before. On a repository with that layout, `conflicts` and `unlinked`
  can fall and the `agent-consistency` row can rise.
