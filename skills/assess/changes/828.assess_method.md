- declared opt-outs and hazards (issue #828): `.assess/agents-declined.json` (who, when, plugin
  version, reason, optional condition ids) sets the conditions it covers to `declined`; listing
  none, it covers every positive `agent_context` or `agent_runtime` condition, so the
  instructions gate cannot hold while it stands. Absence never declines anything, and a
  `.no-<tool>` marker never does. A hazard level may name `blocks = "<gate id>"`; a met hazard
  then holds that gate. The headline opens with a DECLINED badge (owner and reason) and one
  HAZARD line per hazard present, with its fix.
- CI hazards (issue #828): `lib/ci/ci_hazards.py` reads a pull request label that skips every
  check job (a job `if:` with `!contains(github.event.pull_request.labels.*.name, '<label>')`
  and no `||`, or a `needs:` on such a job) and Maven told to ignore test failures
  (`maven.test.failure.ignore` or `testFailureIgnore` true in a CI file, a Jenkinsfile,
  `.mvn/maven.config`, a reactor pom, or a file a CI step leads to through the shared CI-step
  follower). The agent-level decline marker now covers a listed condition id only when that
  condition is tagged `agent_context` or `agent_runtime`.
