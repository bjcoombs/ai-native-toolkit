- merge and review rules kept as code (issue #856): `lib.ci.review_rules` reads a merge queue
  (a `merge_group` workflow trigger or a Mergify `queue_rules`), a policy-bot `.policy.yml`
  that requires an approval, Prow `OWNERS` files with approvers, a committed ruleset or
  protection export that is active and requires review or a merge queue, and a review
  guide directory a pull request workflow names. Each file is parsed (JSON, or YAML through the new
  strict `lib.ci.yaml_tree` reader); anything unsettled reads not measured. OWNERS files that
  name one owner for everything are a catch-all and do not count, mirroring #785. Evidence
  only: the arms attach to the review condition while it is met and move no tally or Step.
  `review_reality.merge_queue` reads the rules' `merge_queue` rule, and a committed merge
  queue where the rules or the protection could not be read.
