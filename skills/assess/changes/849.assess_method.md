- the agent job scope (issue #849): each committed workflow job that runs an agent (the signs
  the agent workflow detector reads, through local actions and reusable workflows; a gh-aw
  source is one job) is read for its effective token scope, `read_only`, `write`, `undeclared`
  or `unread`. A job-level `permissions:` replaces the workflow's, so a job-level write
  override fails; `id-token: write` is not a repository write. Writes are split when gh-aw
  `safe-outputs:` is set or another job that can write (`write` or undeclared scope) `needs:`
  the agent job. A job calling a local reusable workflow takes the called agent jobs' scope,
  capped by its own. A `max-turns` or budget cap is
  recorded as evidence and never counted. Any trigger counts; a `workflow_call`-only workflow
  is read through its caller's job. A workflow on any trigger that calls an agent-named
  reusable workflow in another repository leaves the scope not measured.
