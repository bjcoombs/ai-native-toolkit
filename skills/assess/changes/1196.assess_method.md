- issue #1196, credential in skill text is a finding. The skill-personal-data condition now
  counts `credential` as a kind that makes it unmet, read with a tighter rule for skill text: a
  known provider key at the provider's length anywhere in the text (GitHub, Anthropic, OpenAI,
  Slack, Stripe live, Google, GitLab, npm, Hugging Face, SendGrid, PyPI), or a credential
  assignment, its name prefixed, quoted or neither (`DB_PASSWORD=`, `"API_KEY":`), whose value
  is at least 20 characters with a letter, a digit or both cases, and 3.5 bits of entropy per
  character (2.8 for an all-hex value). Over 2,000 seeded random bodies per shape, recall is at
  least 0.97 for 20- to 40-character hex, alphanumeric and base64 values. Placeholders (`sk-...`, `<API_KEY>`, `YOUR_TOKEN`, runs of one
  character, ascending runs, placeholder words, URLs and paths, the jwt.io sample, and GitHub's,
  Slack's and Stripe's published example tokens on an exact match) are not findings. On the
  labelled fixture set in `tests/test_skill_credentials.py` precision is 1.0 and recall 1.0
  (gate: 0.95 and 0.8). The set is in-sample: the rule was tuned against it, so it bounds the
  known cases only; an out-of-sample false-positive count needs a fleet run over public skill
  repositories, not yet made. A low-entropy example such as `password: hunter2` stays information
  only, in `credential_candidates`.
