- When no import-graph builder covers a repository's dominant source language, structure reads
  not measured with `no_builder:<language>` (issue #825), naming a tool that would build the
  graph where one is known (`jdeps` for Java, Kotlin, Scala and Groovy). No other language's
  graph stands in: a Java repository's vendored JavaScript was measured as its structure and
  could meet layer-2-design conditions. A covered language whose builder found nothing still
  falls back to the largest other graph, and still reads `no_import_graph_<language>` with none.
  The dominant-language count now skips vendored and test trees (`third_party/`, `deps/`,
  `__tests__/`, `spec/` and similar) and test or minified file names for every language, and
  shell counts only when no other language has a file, so a Go module beside vendored C or a
  Python package beside many shell scripts keeps its own graph.
