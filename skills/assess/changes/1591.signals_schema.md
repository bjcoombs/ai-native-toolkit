- `backlog_ready.close_open_ratio` and `close_open_ratio_reason` were added by #1323 (PR #1588) as
  `close_open_ratio_90d` and `close_open_ratio_90d_reason` and renamed before release (#1591): the
  window is `window_days`, which a team can set, so the name no longer says 90. A run at the
  version before reads `backlog_ready.close_open_ratio` as absent.
- `backlog_ready.first_response_met` reads an unanswered issue younger than
  `first_response_max_days` as waiting at least its age, not 0, so it reads false where it read null
  before; `first_response_median_days` reads `window_truncated`, not `empty_window`, when the capped
  window list dropped issues and none read was answered; `outcomes.truncated` is true on a GitHub
  timeline past its item cap or a full GitLab notes page; a GitHub event with no actor counts as a
  person's response, unless the issue's author is gone too, when the response reads unread (#1591).
