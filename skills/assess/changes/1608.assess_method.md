- the gh-aw `imports:` reader (issue #1608) accepts four forms GitHub accepts: `imports: null`
  (or `~`) as no imports, a `...` document-end line closing the frontmatter (any text after it
  still fails closed), a tab after a key's colon, and an imported shared `.md` that opens with
  a `---` rule and never closes it, read as one with no frontmatter. The job's own gh-aw
  source with an unclosed `---` still fails closed. A tab-separated pair inside a flow list
  (`[a:<tab>b.md]`) now fails closed instead of reading as a path. Each file whose frontmatter
  does not parse is named in `agent_instruction_rewrite_unread_files`, and the reach is still
  followed past it; the hazard stays raised while any is named.
