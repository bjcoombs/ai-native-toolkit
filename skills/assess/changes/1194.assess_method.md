- issue #1194, a known lint action inside a local composite action. A step of a local
  composite that uses a known lint action (`astral-sh/ruff-action`, golangci-lint-action,
  reviewdog, super-linter, `pre-commit/action` and the rest `lint_runs` reads at the top
  level) is copied into the calling job with its `with:` block, its `${{ inputs.<name> }}`
  values taken from the caller's literal inputs or the action's defaults, so it reads exactly
  as the same step written in the workflow: credited by default, install only with
  `args: --version`, null with an unsettled input. A nested local composite
  (`uses: ./...` inside the action) is now followed, up to eight levels, with the nested
  step's own `if:` and `continue-on-error` applied to its copies; one that cannot be read
  (missing, not a composite, a cycle back to an action on the path, or past the depth limit)
  stays null (`check_target`), never credited. A remote action inside a composite is still
  not read and never credited. Top-level readings are unchanged.
