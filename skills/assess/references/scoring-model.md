# Scoring model: current state

This page is the single source for how `/assess` and `/fleet` score a repository. It records **current decisions only**. Each item links the issue or pull request that holds the full reasoning. When an issue body or an older comment disagrees with this page, this page is right and the issue is stale. To change the model, raise it on https://github.com/bjcoombs/ai-native-toolkit/issues/740 and update this page in the same change.

**How to read the status of an item.** Each item is marked **Shipped**, with the pull request that merged it, or **Decided, pending**, with the issue that will ship it. The linked issue is the authority on whether a pending item has landed since this page was last edited: when it closes, move the item to Shipped here.

## Glossary

For newcomers, the same words in plain English are in [the glossary](https://github.com/bjcoombs/ai-native-toolkit/blob/main/docs/glossary.md).

| Term | Meaning | Status |
|---|---|---|
| **Condition** | One level of one practice (a maturity-model row), checked with file:line evidence. It is the unit of counting. Each level of a maturity-model row is one condition, `<row id>.<level>` (`lib/scoring/level_tally.py`). | Shipped, https://github.com/bjcoombs/ai-native-toolkit/pull/888 |
| **Input class and grade** | Two layers, both in `lib/scoring/level_signals.py`. Each signal has an **input class**: what its producer read. The seven classes are `config_text`, `head_text`, `head_structure`, `git_history`, `execution_artifact`, `ci_executed` and `platform`. The input class fixes a **grade**. `config_text` grades as `config_only`, `head_text` as `declared`, and `head_structure`, `git_history` and `execution_artifact` as `measured`. `ci_executed` and `platform` grade as `verified`. A condition takes the weakest grade of its criteria. `measured` and `verified` conditions count toward N; `config_only` and `declared` ones are listed, not counted. Earlier lists of five or four "signal classes" in https://github.com/bjcoombs/ai-native-toolkit/issues/783 mixed the two layers. | Shipped, https://github.com/bjcoombs/ai-native-toolkit/pull/802 and https://github.com/bjcoombs/ai-native-toolkit/pull/888 |
| **State** | Each condition has one state per run. **Met**: verified at this commit. **Unmet**: checked and absent, including a practice that was removed. **Not measured**: the run could not see it (headless, no network, shallow history), shown with its reason. **Not applicable**: nothing for it to act on, by a versioned rule. **Declined**: the repository declared an opt-out. | Met, unmet and not measured shipped in https://github.com/bjcoombs/ai-native-toolkit/pull/888. Not applicable shipped through owner exclusions (https://github.com/bjcoombs/ai-native-toolkit/issues/910) and a scan's reason code (`NOT_APPLICABLE_REASONS` in `lib/scoring/level_tally.py`, https://github.com/bjcoombs/ai-native-toolkit/issues/1407): never counted, never holds a gate. Declined shipped in https://github.com/bjcoombs/ai-native-toolkit/issues/828; see Declines below |
| **Requires** | A real dependency between two conditions, written on the level: a condition whose own criteria are met takes the state of the first required condition that is not met. For example, mutation credit requires CI running tests (`layer-6-coverage` level 2 requires `layer-5-ci.1`). | Shipped, https://github.com/bjcoombs/ai-native-toolkit/pull/888 |
| **Truth tag** | The truth a condition keeps honest. There are eight: `behaviour`, `contracts`, `docs`, `structure`, `agent_context`, `agent_runtime`, `governance`, `supply_chain`. Tags are mutual: no tag ranks above another, and they are not a ladder. Every condition has one or more tags. Tags replace layers as the organising frame for reports, `/fleet` roll-ups and advice. | `truth` is required on every condition and listed in the catalog: https://github.com/bjcoombs/ai-native-toolkit/issues/843. The headline's per-tag strip groups by tag (https://github.com/bjcoombs/ai-native-toolkit/issues/844), and so does the `/fleet` per-tag tally in `fleet-data.json` (https://github.com/bjcoombs/ai-native-toolkit/issues/1073; the tag drawings are https://github.com/bjcoombs/ai-native-toolkit/issues/940) |
| **Layer (L0-L8)** | A legacy alias only, so old configs and fleet history resolve: a model with no `truth` on any condition takes its tags from each row's layer, and a model with `truth` on some conditions only is rejected (`MixedTruthError`). New work groups by tag. | Shipped, https://github.com/bjcoombs/ai-native-toolkit/issues/843; the mapping is in `skills/assess/scripts/lib/scoring/levels_fields.py`. Row ids keep their layer numbers, and gates still name a row and a level |
| **Step** | A milestone for how much agent autonomy the repository can support. See Steps below. | Shipped, https://github.com/bjcoombs/ai-native-toolkit/pull/888 |
| **Gate** | A condition a Step requires. Gates are all a Step reads (https://github.com/bjcoombs/ai-native-toolkit/issues/1083). Gates are named after their condition, not after a tag or a layer. Gates read state, never grade: a declared condition (an instruction file is text at HEAD) or a config-only one holds its gate while staying out of N. | Shipped, https://github.com/bjcoombs/ai-native-toolkit/pull/888 |
| **Hazard** | A harmful practice, often two good practices combined (for example, CI plus a label that skips it). A hazard condition is `polarity = "hazard"` in the maturity model; one that names `blocks = "<gate id>"` holds that Step gate while it is met. Hazards are listed apart from the tally (`hazards` in the level result, each with the check manifest's fix) and never subtract from N. | Shipped in https://github.com/bjcoombs/ai-native-toolkit/issues/828, with two hazards that hold the `ci_runs_tests` gate: `ci-skip-label` (a pull request label that skips every CI check) and `ci-test-failures-ignored` (Maven told to ignore test failures), read by `lib/ci/ci_hazards.py`. https://github.com/bjcoombs/ai-native-toolkit/issues/857 added `ci-instructions-unchecked`, which holds the `instructions` gate while every pull request check workflow filters an instruction file out with `paths` or `paths-ignore` |
| **Badge** | Do not use this word for a condition. In the report it means a state marker only (HAZARD, DECLINED, NOT MEASURED). | Shipped in the per-tag strip, https://github.com/bjcoombs/ai-native-toolkit/issues/844 |

## The headline

**Shipped** in https://github.com/bjcoombs/ai-native-toolkit/pull/894 (`lib/scoring/headline.py`), with the per-tag strip added in https://github.com/bjcoombs/ai-native-toolkit/issues/844 and the count taken out of the Step, the Next line and the badge in https://github.com/bjcoombs/ai-native-toolkit/issues/1083:

The report opens with the top card (`lib/top_card.py`, https://github.com/bjcoombs/ai-native-toolkit/issues/1252), which states each fact once, before any section heading:

```
Step 3 of 4: unattended agent PRs.
Holding: 2 of 3 Step 4 gates held at `600cca4` · 9 of 12 measured catalogue conditions met, 2 verified.
Blocks Step 4: no coverage gate is enforced. `skills/assess` already does this; copy it.
Since last run: 1 action closed.
Start here: add `fail_under` under `[tool.coverage.report]` in `pyproject.toml`
Done when: the CI test job runs coverage with `fail_under` set and is green.
```

The headline block under it keeps the rest:

```
Catalogue coverage: 4 not measured (needs a full run: 1, no remote: 3) · model <version>
By tag: behaviour 3 of 4 · structure 4 of 5 · agent_context 2 of 2 · governance 0 of 1 (NOT MEASURED: 3)
```

- **The Step and the blocking gate lead.** A Step reads its gates and nothing else (see Steps), so a change to the catalogue never moves it and these lines are stable across model versions. Below the top Step the Blocks line names the blocking gates, in Step order, and the unit a monorepo roll-up finds already holding the first one. It never says "N more practices" and never picks a condition by model order. At the top Step the card reads "Holding Step N of N · K advisories, none blocks the Step", where K counts the unmet conditions that block no Step gate. Each card has one Start here and one Done when, from the first open action of `.assess/actions.json` by rank, else the blocking gate as a task.
- **The catalogue coverage.** The card's Holding line carries N, M and the verified share; the headline's coverage line carries the not-measured count and its reasons. It says how much of the catalogue this run could read, and it is never a progress figure: no Step, Next line or badge reads it. N counts both `measured` and `verified` conditions, with the verified share of N beside it ("2 verified"). N is the number of met, counted conditions. M is the number of counted conditions that were **measured** (met or unmet). Not-measured conditions are excluded from both N and M and shown beside the count with their reasons. An unknown never earns anything, so a blind run never raises N. A run that can see more, or less, can still change N and M, which is why the not-measured count and its reasons sit on the same line. When a new maturity-model version changes the conditions, the move is shown in the Recount, not as a drop: on the first `/fleet` run under the new version, stored scans are re-scored under it and each move the rule change alone caused is listed, saying the repository did not change (`lib/fleet/fleet_rescore.py`, `lib/fleet/fleet_credit.py`, shipped in https://github.com/bjcoombs/ai-native-toolkit/pull/803).
- **The per-tag strip.** One cell per truth tag that a condition in the result carries, counted like the tally over the conditions with that tag. A condition with several tags appears in each tag's cell, but N counts it once. NOT MEASURED, HAZARD (a hazard condition met) and DECLINED are badges with their counts, shown only when non-zero. The headline block also carries `verified` and `tags` as numbers, so counts-only output keeps the strip without its text.
- **The inputs.** The headline is computed by the deterministic core from the run's `level` block and is never set by the LLM. That block depends on the commit, the maturity-model version, the committed config, and what this run could measure (for example, whether it had GitHub access). Two runs at one commit with the same access print the same headline. Changes are attributed by cause: repo, rules or scanner (https://github.com/bjcoombs/ai-native-toolkit/issues/771, https://github.com/bjcoombs/ai-native-toolkit/issues/774).
- **There is no "Level N", no 0-8 score, no mean and no band name.** The "X / 8" headline was retired in https://github.com/bjcoombs/ai-native-toolkit/pull/894. The `/fleet` roll-up shows, per unit and `team` row, the lowest level plus "N of M measured" (https://github.com/bjcoombs/ai-native-toolkit/issues/772). There N and M count **repositories**, not conditions: M is the unit's repositories and N those measured on that row, so an unknown or failed repository stays in M and is never read as 0 (`skills/fleet/references/fleet-data.md`, Roll-ups). It is a different number from the per-repository tally above. Diagrams that still average repository levels are open in https://github.com/bjcoombs/ai-native-toolkit/issues/806.

- **Since last run.** The `log.md` entry opens with what changed since the previous run, and the card states it in one line under the dark-cockpit rule: a part appears only when it is non-zero, changed or unknown, and nothing moved means no line (`lib/since_last_run.py`): the actions closed since then, each with its `completed_sha` from the committed `actions.json` (an action counts when its commit is on HEAD's history and not an ancestor of the commit the previous run measured, so a branch commit squashed away is never credited), and the gates gained or lost. The baseline is the previous run's commit and held gates in the committed `prior-level.json` (https://github.com/bjcoombs/ai-native-toolkit/issues/1122), so a fresh clone or CI has it; the gitignored `run-context.json` is the fallback. A run with no committed baseline reads "This run is your baseline; the next `/assess` run reports what moved." once; a previous run that cannot be read gives "not known", never 0. This is where a team sees credit for its work, including for taking a practice away: a `remove` action (instruction text the placement scan flags) is credited as "Pruned: <practice>, saved <cost>" once the file has stayed unflagged and no gate lost for two runs on new commits (`lib/pruning_ledger.py`, https://github.com/bjcoombs/ai-native-toolkit/issues/1084). The number of practices is never scored, and a credited removal moves no Step. Shipped in https://github.com/bjcoombs/ai-native-toolkit/issues/1083.
- **The badge summary** is `Step 3 · 2 practices fully in place · next: coverage gate`: the Step, the practices at their top level (left out at 0, https://github.com/bjcoombs/ai-native-toolkit/issues/1334) and the first gate that blocks the next one, with no tally count. At the top Step it is `Step 4 · 5 practices fully in place · all gates held`. The `log.md` readiness line is the same text. Shipped in https://github.com/bjcoombs/ai-native-toolkit/issues/1083.

## Steps

**Shipped** in https://github.com/bjcoombs/ai-native-toolkit/pull/888, as the `[[steps]]` table in `skills/assess/levels/default.toml`:

| Step | Name | What it supports | Gate added at this Step |
|---|---|---|---|
| 1 | `Assisted` | one supervised agent | none |
| 2 | `Supervised agent PRs` | agent PRs a person reviews | `instructions`: an instruction file an agent reads (`layer-0-instructions` level 1) |
| 3 | `Unattended agent PRs` | agent PRs without a person watching | `ci_runs_tests`: CI runs the tests, unmasked (`layer-5-ci` level 1, https://github.com/bjcoombs/ai-native-toolkit/issues/775) |
| 4 | `Autonomous loops` | marathon-style autonomous loops | `coverage_gate`: an enforced coverage gate (`layer-6-coverage` level 1) |

- Gates accumulate, so Step 4 needs all three.
- **A Step needs its gates and nothing else, and the code enforces it.** There is no count threshold, so a condition added to the catalogue that a repository already meets never moves its Step. `lib/scoring/level_tally.py` builds a Step's blockers from its gates alone, `lib/scoring/levels.py` refuses a `threshold` key in `[[steps]]` with a message naming the change, and `tests/test_level_tally.py` pins the invariant by adding met, counted conditions to a fixture and checking that its Step does not move. Shipped in https://github.com/bjcoombs/ai-native-toolkit/issues/1083, which removed the thresholds of 0, 1, 3 and 5 that https://github.com/bjcoombs/ai-native-toolkit/pull/888 shipped.
- Gates are staged because a 36-repository private fleet spike found an enforced coverage gate in none of the 36. Requiring every gate for every Step would hold all of them at Step 1 (https://github.com/bjcoombs/ai-native-toolkit/issues/744).
- **Owner exclusions** shipped for the repository side in https://github.com/bjcoombs/ai-native-toolkit/issues/910. `.assess/config.toml` takes `[checks] exclude = [{ id = "<condition id>", reason = "...", kind = "..." }]`, where `kind` is one of `not_applicable`, `measured_elsewhere`, `tool_unsupported`, `false_positive` or `other`. An excluded condition reads `not_applicable` with `disposition: excluded_by_owner`. It neither earns nor costs, because it leaves the denominator. An excluded gate condition never holds its gate, so the Step it gates stays out of reach while the exclusion stands. An entry with no reason is skipped with a warning. The `--fleet-config` side waits on the method stamp (https://github.com/bjcoombs/ai-native-toolkit/issues/952), so a fleet exclusion cannot reset history.
- **Hazards and declines** shipped in https://github.com/bjcoombs/ai-native-toolkit/issues/828 (`lib/scoring/level_tally.py`): a met hazard that names `blocks` holds that gate, and a declined condition never holds a gate. Each gate reports one blocker: the gate's own first condition that is not met, else a met hazard that names it. A hazard is listed in `hazards` either way. A hazard that is not measured blocks nothing. Neither changes N or M.

## Declines

**Shipped** in https://github.com/bjcoombs/ai-native-toolkit/issues/828. A repository that decided not to enable agents commits `.assess/agents-declined.json`:

```json
{"declined_by": "<owner>", "declined_at": "YYYY-MM-DD", "plugin_version": "<x.y.z>", "reason": "<why>", "conditions": ["<condition id>"]}
```

- `conditions` is optional. Left out, the record covers every positive condition tagged `agent_context` or `agent_runtime`, which includes the `instructions` gate. Written, it covers only the condition ids it lists that carry one of those two tags, so a malformed value covers fewer conditions, never more, and the marker never takes a non-agent condition, such as a coverage gate, out of the denominator. A hazard is never declined.
- A covered condition reads `declined` whatever its criteria say. It is never met and never counted, it leaves the denominator, and it never holds a Step gate, so the Step it gates stays out of reach while the decline stands. An owner exclusion of the same condition wins.
- The headline opens with a DECLINED badge naming the owner, the date and the reason.
- Absence never produces `declined`. The tool markers (`.assess/.no-<tool>`) are a separate record and never set it.
- Interface for detectors: a decline is a `DeclineRecord` (`lib/scoring/level_result_types.py`), passed to `level_result(..., declines=...)` or read from the run context's `owner_exclusions.declines`. Detecting policy files and disabled hooks that set it is https://github.com/bjcoombs/ai-native-toolkit/issues/846 and https://github.com/bjcoombs/ai-native-toolkit/issues/851.

## What else is decided

- **Rules for new conditions.** Decided, pending.
  - A condition is accepted only if, across the 12-repository corpus, at least one repository meets it and at least one does not (https://github.com/bjcoombs/ai-native-toolkit/issues/842).
  - A condition with an empty denominator reads not measured, never met (https://github.com/bjcoombs/ai-native-toolkit/issues/827).
- **The exit rule for conditions.** Decided, pending in https://github.com/bjcoombs/ai-native-toolkit/issues/1086.
  - Each condition PR states a predicted direction on the agent-outcome measure (https://github.com/bjcoombs/ai-native-toolkit/issues/1085) and a review date. They are the `predicted` and `review` keys on the condition's level in the maturity model (`lib/scoring/levels_fields.py`). They change no state, count or Step, and the catalog shows them.
  - A condition with no review date is never demoted. No existing condition has one: none is backfilled.
  - A condition whose review date has passed, measured on at least 10 repositories on each side with a 95% interval for the effect that includes 0, is demoted to informational. It shows in the report and counts toward nothing. A condition that holds a Step gate is never demoted, so a demotion never moves a Step.
  - Demotion is decided only by the fleet, from measured outcomes. `fleet.py --levels` estimates each condition's effect from its run and history (`condition_effect.json`), writes the decision with its evidence to `demotions.json` and keeps it in the run history. No `--fleet-config` or `.assess/config.toml` key reads or sets a demotion, so a repository cannot demote its own conditions, and a plain `/assess` demotes nothing.
  - A demoted condition keeps its state and carries `disposition: "demoted_by_exit_rule"`. It is listed, never counted.
- **Name-only agent matches become hints.** Decided and shipped in https://github.com/bjcoombs/ai-native-toolkit/issues/883 (maintainer decision of 2026-11-22). A built-in agent match with no `[bot]` suffix or verified app identity, such as `noreply@anthropic.com`, the `copilot` username or a GitLab username match, becomes a candidate that needs confirmation and is not counted until it is confirmed. `[bot]`-suffix and co-author-trailer rules stay counted.
- **Config-only signal renames.** Shipped in https://github.com/bjcoombs/ai-native-toolkit/pull/911, completing https://github.com/bjcoombs/ai-native-toolkit/issues/783: `ci_checks.test_or_lint_runs` is now `ci_checks.test_or_lint_configured`, and `coverage_gate.enforced` is now `coverage_gate.configured`. Pure renames go through `SIGNAL_ALIASES` in `lib/signal_aliases.py` (https://github.com/bjcoombs/ai-native-toolkit/issues/970): a re-score shows no Recount line, fleet compare lists no added or removed leaf for them, and a `--levels` model naming an old path loads under the new one with one deprecation line on stderr. The classification shipped earlier in https://github.com/bjcoombs/ai-native-toolkit/pull/802.
- **Spread comes from interaction, guard and contradiction conditions, not from more file-presence checks.** The candidate conditions from the calibration are the children of https://github.com/bjcoombs/ai-native-toolkit/issues/826 (https://github.com/bjcoombs/ai-native-toolkit/issues/845 to https://github.com/bjcoombs/ai-native-toolkit/issues/858).
- **No general dependency graph.** Dependencies are `requires` between conditions plus the three gates.
- **Outcome claims** (do agents do better on repositories that meet more conditions?) are a separate research track. They are reported as "observed" and are never added to N.
