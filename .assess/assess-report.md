<summary>🧭 How to read this report (framing & method)</summary>

**What this is ultimately measuring.** When you hand work to an AI here, does it behave like a brand-new hire or like an engineer who has been in the org eighteen months? The difference is *externalized context*: knowing where things live, which contracts are load-bearing, where the minefields are. An AI contributor starts every session with an empty head and one narrow context window, so this report scores how much of the tenured engineer's map the codebase has made explicit and navigable. **Legibility you can trust, not omniscience you can't.** The write-side layers read not as a leash on the agent but as the guardrails that protect any contributor from costly mistakes by design. A **Missing** there means the codebase asks the contributor to be careful where it could instead make the wrong move hard to make.

This is an improvement roadmap, not a verdict. It measures one thing: **is the codebase kept honest, not just scaffolded.** It pairs three views: the complexity heatmap (where the codebase is today), the doc graph (whether an agent can navigate it), and the 0-8 score (what keeps it from getting worse) across read-side, write-side and meta bands. A codebase can be 8/8 and still on fire, or 2/8 with a calm treemap.

**Each layer is a sense the agent needs, not a box to tick.** A Missing or Partial locates where someone working here is partly blind, and the Gap column says what would restore the view. **Layer 1 (Runtime Legibility) is the agent's attention-sense.** A repo with no deployed runtime answers it through complexity, churn and reachability, so the heatmap and the dead-code scan *are* its observability; a low score there means look through those instruments.

**The legacy-transition lens.** "Legacy code is code without tests" (Feathers, *Working Effectively with Legacy Code*, 2004): characterize current behaviour, find a seam, then refactor. Don't rewrite - strangle (Spolsky 2000; Fowler's Strangler Fig). Hotspots and change-coupling are the map (Tornhill). Decide per component (the 7 Rs).

**How it's measured.** Static analysis, git history and graph metrics over the docs and code. The model writes the prose around those numbers and does no scanning itself, which keeps the structural findings reproducible run to run.
