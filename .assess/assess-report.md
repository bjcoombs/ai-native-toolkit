<summary>🧭 How to read this report (framing & method)</summary>

**What this is ultimately measuring.** When you hand work to an AI here, does it behave like a brand-new hire or like an engineer who has been in the org eighteen months? The difference is *externalized context*: knowing where things live, which contracts are load-bearing, where the minefields are. An AI contributor starts every session with an empty head, so this report scores how much of the tenured engineer's map the codebase has made explicit and navigable. **Legibility you can trust, not omniscience you can't.** The write-side layers (linters, architecture tests, CI gates, coverage, review automation) are the guardrails that protect any contributor, human or AI, from costly mistakes by design. A **Missing** there means the codebase asks the contributor to be careful where it could make the wrong move hard to make.

This is an improvement roadmap, not a verdict. It measures one thing: **is the codebase kept honest, not just scaffolded.** It pairs three views: the complexity heatmap (where the codebase is today), the doc graph (whether an agent can navigate it), and the 0-8 score (what keeps it from getting worse).

**Layer 1 on a repo with no runtime.** Layer 1 is the agent's attention-sense: which parts are live, which need attention, which are dead weight. This repo ships skills and scripts, not a service, so the complexity heatmap and the dead-code scan are its observability. A Missing here means *look through those instruments*, not that the agent is blind.

**The legacy-transition lens.** "Legacy code is code without tests" (Michael Feathers, *Working Effectively with Legacy Code*): pin current behaviour with characterization tests and find a seam before refactoring. Prefer Martin Fowler's Strangler Fig to a rewrite. The hotspot and change-coupling views are Adam Tornhill's analyses; treat the vivid-red hotspots and `hidden_coupling` seams as the worklist.

**How it's measured.** Static analysis, git history and graph metrics over the docs and code. The model writes only the prose around those numbers.
